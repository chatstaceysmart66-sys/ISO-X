# ISO-X 0.2.0 — Gap Analysis / تقرير الفجوات

**تاريخ التقرير:** 2026-10-18
**النتيجة:** حزمة مصدر مرشحة للاختبار، ليست Release قبولًا نهائيًا. لا يوجد ISO أو فيديو قبول فعلي ضمن هذه الحزمة.

## ملخص الحالة

| البند | الحالة | الدليل الحالي / النقص |
|---|---|---|
| واجهة GTK3 | منفذة مصدريًا | `app/iso_x_gtk.py`; فحص syntax ممكن، لكن لا يمكن تنفيذ GUI في بيئة بلا GTK display/GI |
| صفحات العمل/التطوير/الويب/الشخصي | أولية | مفاتيح 1–4 وأزرار تنقل داخل الواجهة؛ Ctrl+عجلة الماوس وسحب 3 أصابع ومساحات عمل حقيقية غير منفذة |
| مدير الملفات ثنائي اللوحين | أولي | تصفح مسارات ومعاينة نصية؛ ليست كل أنواع المعاينة (PDF/فيديو/صور) مدمجة |

| نص عربي 3D Extruded | غير مكتمل | يظهر كنص Text2d مسطّح؛ لا يوجد extrusion أو دوران كامل 360° أو تجميع حرفي متدرج |
| Boot splash قبل مصادقة المستخدم | غير مكتمل | مشهد Bevy يبدأ داخل جلسة Openbox بعد المصادقة، لا قبل شاشة LightDM |
| SQL 0.2.0 | منفذ | حقول hash/fingerprint/state وجدول الاستخدام المحلي؛ اختبارات SQLite موجودة |
| ISO قابل للإقلاع | غير مبني | لا يوجد `ISO-X-0.2.0-live-amd64.iso` في التسليم |
| قياسات SLA | غير متوفرة | لا توجد مخرجات systemd-analyze/free/top على VM 2-core/1GB |
| مقارنة Windows | غير متوفرة | لم تتوفر نفس آلة الاختبار ونتائجها |
| فيديو إقلاع/3D/قياسات | غير موجود | أداة تسجيل مساعدة فقط؛ يلزم تسجيل فعلي من مضيف يعرض VM أو جهاز الاختبار |

## ما تم اختباره في بيئة المصدر

- بناء قاعدة SQLite داخل الذاكرة والتحقق من وجود الجداول والحماية من UPDATE/DELETE عبر trigger.
- اختبار تشفيري مصغّر يولد شهادة اختبار مؤقتة، يتحقق من الحمولة الأصلية ثم يثبت أن تغيير الحمولة يفشل التوقيع. هذا **لا** يثبت أن وحدة kernel قد بُنيت أو أن initramfs يمنع إقلاعًا فعليًا.
- `py_compile`, `bash -n`, وفحوص ملفات المصدر التي تنفذها `tests/smoke.sh`.
- تحقق SQL من أن `watermark_key` و`watermark_value` غير قابلين للتعديل، بينما يمكن تحديث بيانات التوقيع الوصفية؛ وتحقق ترحيل 0.1.0 من استبدال trigger القديم.

## شروط قبول الإصدار الحقيقي

1. استخدام مفتاح إصدار حقيقي محفوظ خارج المستودع؛ مراجعة تطابق الشهادة والثقة بها في kernel/MOK قبل تفعيل enforcement.
2. نجاح أمر build على مضيف Bookworm-compatible مع وصول حزم Debian والـ Rust crates.
3. فحص `file`, `sha256sum`, و`xorriso -indev` للصورة الناتجة ثم الإقلاع باستخدام VM.
4. اختبار حذف الوحدة وتغييرها بعد بناء الصورة: يجب أن تظهر رسالة guard وتتوقف الجلسة؛ كما ينبغي توثيق حدود العبث بالـ initramfs/bootloader.
5. اختبار إقلاع fresh على VM مقيّدة إلى نواتين وRAM 1024MB. تسجيل systemd-analyze، free -h، top، ps aux، zramctl، وحالة Secure Boot.
6. تسجيل فيديو 60 ثانية من مضيف VM يلتقط إعادة التشغيل، المشهد، سطح المكتب والقياسات؛ عدم نشر الفيديو قبل مراجعة أنه من البناء نفسه.
7. قياس رام الخمول الفعلية. إذا تعدت 180MB، نشر أكبر العمليات وخطة خفض، لا ادعاء النجاح.

## خطة العمل المتبقية (ترتيب، لا وعود زمنية)

- **مرحلة A:** جمع مفتاح العميل، بناء ISO، حفظ SHA256 وسجلات build.
- **مرحلة B:** اختبار QEMU/جهاز فعلي، إصلاح أي فشل في initramfs/module/LightDM/GTK.
- **مرحلة C:** قياسات الأداء والفيديو وتكرار الاختبار بعد تغييرات الأداء.
- **مرحلة D:** استكمال greeter ثلاثي الأبعاد آمن يتكامل مع LightDM/PAM، Arabic glyph shaping وحروف Extruded، ودعم previews لكل أنواع الملفات.
- **مرحلة E:** توقيع سلسلة الإقلاع (مثل UKI/Secure Boot) إذا كان المطلوب مقاومة خصم قادر على تعديل ISO، مراجعة أمنية مستقلة، ثم إصدار قبول موثق.
