# وثيقة بنية ISO-X — الإصدار 0.4.0

## الحالة
ISO-X هو نظام Live مبني على Debian Trixie amd64، وليس نواة مستقلة مكتوبة من الصفر. المصدر الحالي يحدد إعدادات بناء ISO؛ حتى توثيق هذا الفحص لم تُنتج صورة ISO نهائية ولم يُختبر الإقلاع أو العتاد. الحالة الدقيقة في `AUDIT.md`.

## طبقات النظام

1. **Firmware / Secure Boot**: سلسلة الثقة الأولى تأتي من الجهاز وإعدادات Secure Boot/UEFI. لا يستطيع برنامج داخل ISO أن يجعل العلامة غير قابلة للتجاوز إذا كان صاحب الجهاز قادرًا على تعديل bootloader والـ initramfs.
2. **Linux kernel**: نواة Debian القياسية، مع وحدة خارجية `isox_watermark.ko`. تُترجم الوحدة لكل kernel مثبت أثناء بناء الصورة وتوقّع بواسطة مفتاح الإصدار المقدّم خارجيًا.
3. **initramfs integrity guard**: hook يضم الوحدة والملفات العامة وتوقيع OpenSSL إلى initramfs. سكربت `init-premount` يتحقق من بصمة الملف وتوقيع الإصدار ثم يحاول تحميل الوحدة. عند الفشل يعرض سببًا واضحًا ويوقف تقدم Live ISO إلى سطح المكتب مع shell إنقاذ.
4. **Display manager / Authentication**: LightDM/PAM يبقى مسؤولًا عن مصادقة كلمة المرور. مشهد Bevy لا يقرأ كلمة المرور ولا يستبدل PAM.
5. **Window manager**: Openbox.
6. **Desktop shell**: واجهة GTK3 في `app/iso_x_gtk.py`. Tkinter 0.1.0 محفوظ كمرجع تاريخي؛ GTK3 هو مدخل الواجهة الحالي في مصدر 0.4.0.
7. **Web browser**: Firefox ESR مع `firefox-esr-l10n-ar` وخطوط عربية، وتعيين صفحة بدء محلية `file:///usr/share/iso-x/start.html` عبر تفضيلات Debian؛ NetSurf GTK متصفح خفيف إضافي، وقد تكون توافقاته مع مواقع حديثة محدودة. ملفات المصدر تحدد الحزم والتفضيلات، لكن فتح المتصفح والرسم العربي يحتاج اختبارًا داخل ISO مبني.
8. **Data**: SQLite محلية داخل `~/.local/share/iso-x/iso-x.db`. لا توجد نقطة اتصال Telemetry. سجلات الاستخدام المحلية مرتبطة باختيار التطبيق فقط، وميزة preload متوقفة افتراضيًا.
9. **Memory**: خدمة ZRAM تستخدم نصف RAM مع zstd و`vm.swappiness=10`. خدمة preload اختيارية ولا تبدأ تطبيقات؛ تكتفي بتدفئة صفحات الملفات التنفيذية إذا كانت مفعّلة والذاكرة المتاحة كافية.

## علامة المطوّر والتوقيع
- اسم المطوّر المشفّر بصيغة XOR داخل ملف ترويسة مولّد ويُفكّ عند تحميل الوحدة. هذا إخفاء بسيط للنص وليس تشفيرًا قويًا.
- توقيع Linux module (PKCS#7) وتوقيع OpenSSL منفصل للملف النهائي وظيفتان مختلفتان. التوقيع لا يثبت الثقة وحده؛ يجب أن تكون شهادة الوحدة موثوقة لدى النواة عند تفعيل enforcement. في أجهزة Secure Boot يلزم عادةً إدخال شهادة موثوقة عبر MOK أو بناء نواة/سلسلة إقلاع تثق بالمفتاح.
- حارس initramfs يكتشف حذف الوحدة أو تغييرها دون إعادة توقيعها، لكنه ليس حلًا مضادًا لتعديل الـ boot chain بالكامل. لا يمكن ضمان علامة غير قابلة للإزالة على جهاز يتحكم مالكه بمفاتيح الإقلاع وصلاحيات root.
- المفتاح الخاص يُمرّر وقت البناء فقط عبر `ISOX_RELEASE_KEY`، ولا يجب تضمينه في المصدر أو ISO. سكربت البناء يحذفه من نسخة chroot قبل إخراج الصورة.

## محرك Bevy
`three-d-login/` يحوي مشروع Rust/Bevy 0.19.1 لمشهد ترحيبي ثلاثي الأبعاد: كاميرا 3D، سداسي وأجنحة هندسية مضيئة، جزيئات مدارية، بلورات، لوح شبيه بالزجاج، واسم المطور كنص داخل المشهد. عند Enter أو بعد نحو 9 ثوانٍ ينتقل إلى واجهة المستخدم. هو مشهد ترحيبي بعد مصادقة LightDM، وليس greeter يُدخل كلمات المرور.

ما زال نص الاسم غير مبثوق كشبكة حروف Extruded ثلاثية الأبعاد، ولا يوجد تأثير حقيقي مرتبط بمدخل كلمة المرور أو تكسر النافذة عند نجاح PAM. لا يجوز وصف هذه التأثيرات بأنها مكتملة.

## قاعدة البيانات
راجع `db/schema.sql`. تشمل `users`, `app_registry`, `installed_app_permissions`, `fs_index`, `perf_logs`, `sys_snapshots`, `dev_envs`, `privacy_settings`, `kernel_watermark`, `local_app_usage`, و`schema_migrations`. جدول العلامة يحفظ رقم الوحدة وبصمتها وبصمة شهادة الإصدار وحالة التحقق عند إنشاء DB جديدة بعد البناء. تريغرات SQLite تمنع تغيير حقول هوية المطوّر أو حذف الصف عبر SQL الاعتيادي، بينما تسمح بتحديث بصمة الوحدة وحالة التوقيع الوصفية. هذه التريغرات لا تمنع root من إعادة بناء الملف أو تغيير المخطط.

## إقلاع وبناء
`./build.sh` (واجهة أمر واحد) يمرر التنفيذ إلى `scripts/build-iso.sh` الذي ينفّذ `cargo build --release` ثم Debian Live Build لـ Trixie amd64. يحتاج مضيف بناء Linux بصلاحيات root، `live-build`, `xorriso`, `debootstrap`, `mksquashfs`, إصدار Rust stable متوافق مع Bevy 0.19.1، OpenSSL وخط Noto Arabic. يحتاج أيضًا مفتاحًا وشهادة الإصدار عبر متغيرات البيئة. لم يُنتج ISO في بيئة التدقيق: `lb`, `xorriso`, `debootstrap`, `mksquashfs`, `cargo` و`rustc` غائبة، و`apt-get update` لم ينجح بسبب تعذّر الوصول إلى المستودعات؛ انظر `AUDIT.md` للسجلات الدقيقة.

## قيود الأداء
لا توجد نتائج قياس موثقة على CPU بنواتين وRAM 1GB/GPU مدمج في هذا التسليم. الهدف 30 ثانية إقلاع و180MB RAM خمول و2% CPU هي أهداف قبول وليست نتائج. استخدم `scripts/collect-performance.sh` بعد الإقلاع الفعلي، وسجّل الفيديو على مضيف VM بواسطة `scripts/record-demo.sh`.
