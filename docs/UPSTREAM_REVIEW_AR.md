# تقرير فحص ودمج مصادر Windows Lite في ISO-X

## القرار التنفيذي

تم اعتماد دمج آمن لأفكار سهولة الاستخدام والعلامة البصرية فقط، وليس دمج نظام Windows أو صورة ISO أو إعدادات إزالة مكونات Windows في نظام Debian/Linux. السبب التقني: NTLite/XML وملفات Registry موجهة إلى Windows offline image/Explorer، ولا تُطبق على filesystem أو واجهة Linux.

## ما تم دمجه عمليًا في ISO-X

1. لوحة ترحيب عربية باسم ISO-X تستخدم شعار التنين الخاص بالمشروع مع قياس الصورة قبل عرضها لتجنب تكبير PNG 1024×1024 داخل النافذة.
2. أزرار تشغيل للمتصفح، الملفات، مركز التطبيقات، إعدادات النظام والشبكة، مراقبة النظام، والطرفية؛ كل أمر يُنفذ كقائمة arguments ولا يستخدم `shell=True`.
3. عرض محلي لمعلومات النواة والمعمارية وعدد المعالجات وRAM والمساحة الحرة؛ لا يوجد إرسال بيانات استخدام.
4. تأكيد تحذيري قبل تشغيل مثبت القرص لتقليل احتمالية تثبيت غير مقصود قد يمسح البيانات.
5. اختصار سطح مكتب بالعربية، مدخل في قائمة Start الخاصة بـ Openbox، والاختصار `Super+W`.
6. تثبيت حزمة الأيقونات المطلوبة وملفات دليل ISO-X وإشعارات المصادر داخل الصورة التي سينشئها سكربت البناء.
7. اختبار مصدر جديد يتحقق من الربط بين البرنامج وسكربت البناء والاختصارات وتوثيق المصادر.

## حدود القبول

الاختبارات التي اجتازت هنا هي اختبارات المصدر والثوابت البرمجية. لم يُبنَ ISO في هذه البيئة ولم تُختبر لوحة GTK داخل جلسة رسومية أو داخل QEMU. نجاح `tests/smoke.sh` لا يثبت إقلاع النظام أو عمل كل زر بعد الإقلاع. راجع `STATUS_AR.md` ومصفوفة `docs/QEMU_ACCEPTANCE_AR.md` قبل وصف الإصدار بأنه جاهز للتثبيت.
