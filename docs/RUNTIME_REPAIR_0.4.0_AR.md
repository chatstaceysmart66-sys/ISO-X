## نتائج المصدر المحلية

شُغّل `scripts/run-source-checks.py` على الحالة الحالية: 65 فحصًا ناجحًا، صفر فشل، وحالة pytest واحدة متخطاة؛ أربع بوابات `NOT_RUN` بسبب غياب `sfdisk` وXvfb/أدوات X و`ShellCheck` و`desktop-file-validate`. لا تتضمن هذه النتيجة بناء ISO أو إقلاع BIOS/UEFI.

اختبار التبديل بين مجموعات XKB واختبارات إغلاق/تحجيم النوافذ ستعمل ضمن `source-check` في GitHub Actions. لا تُعد اختبارات Wi-Fi الحقيقي، اتصال الإنترنت وDNS على بطاقة فعلية، أو persistence عبر USB مقبولة حتى تُسجل أدلة مستقلة لها.

## تدقيق إدارة النوافذ — 2026-10-24

### السبب الجذري والإصلاح

نافذة ISO-X الرئيسية نافذة GTK أصلية قابلة لتغيير الحجم؛ لا تستخدم نافذة بلا إطار أو شريط عنوان مخصص. زخارف `NLIMC` وأزرارها مصدرها Openbox. كان ملف `desktop/openbox-rc.xml` المخصص يطلب رسم أزرار التصغير والتكبير والإغلاق، لكنه لم يعرّف سياقات النقر `Iconify` و`Maximize` و`Close`، ولذلك كانت الأزرار ظاهرة بلا أفعال. كما اقتصر تحريك الإطار على `Alt+السحب الأيسر` وتغيير حجمه على `Alt+السحب الأيمن`، من دون سحب شريط العنوان أو الحواف والزوايا المعتادة. وأدى استبدال إعداد Openbox الافتراضي أيضاً إلى إسقاط اختصارات `Alt+F4` و`Alt+Tab`.

أضيفت أفعال Openbox القياسية لأزرار الإطار، وسحب شريط العنوان، وسحب كل حافة من الحواف الأربع والزوايا الأربع، مع إبقاء اختصارات Alt الموجودة وإضافة إغلاق النافذة والتبديل بين النوافذ. يثبت `scripts/build-iso.sh` نسختي الإعداد في `/etc/xdg/openbox/rc.xml` وملف المستخدم الابتدائي، ويشغّل اختبار Xvfb الآن ملف ISO-X نفسه بدلاً من إعداد النظام الافتراضي.

### ما بقي محجوباً

لم يُبن ISO ولم يُجر اختبار BIOS أو UEFI: `lb` و`qemu-system-x86_64` غير متاحين، المستخدم الحالي UID 1000، والمساحة المتاحة 17 GiB فقط. لم يُعثر على ملف ISO في الشجرة. كما لم يُنفذ اختبار ستة تطبيقات مستقلة أو جولات 6/5 GiB RAM؛ معظم التطبيقات المستهدفة (مدير الملفات، الطرفية الرسومية، المحرر، المتصفح ومدير المهام) غير مثبتة في المضيف، المتاح منها للاختبار التفاعلي هو `xterm`، والمضيف يعرّف معالجين منطقيين. لا تمثل نتائج Xvfb إثبات أداء أو إقلاع أو دعم عتاد ISO-X.
