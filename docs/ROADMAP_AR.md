# خارطة طريق ISO-X بعد الإصدار المصدري 0.2.0

## المرحلة A — بناء وتكرار موثوق
- تشغيل `scripts/build-iso.sh` على مضيف Debian amd64 مع Rust stable المتوافق مع Bevy 0.19.1، حزم Live Build ومفتاح إصدار محفوظ خارجيًا.
- التأكد من أن المفتاح الخاص لا يُضمّن إلى ISO أو ZIP، وحفظ log البناء وSHA-256 للصورة.
- اختبار بنية initramfs وتوقيع الوحدة على kernel Trixie من نفس الصورة.

## المرحلة B — قبول الإقلاع
- تشغيل الناتج على QEMU بمواصفات 2 vCPU و1024MB RAM مع تسجيل فيديو من المضيف.
- اختبار الإقلاع الطبيعي، وفشل التحقق بعد التعديل، ومسار الإنقاذ، ثم تسجيل systemd-analyze/free/top/ps/zramctl.
- مقارنة Windows فقط إذا أمكن الاختبار على نفس الجهاز والظروف؛ لا تُخترع أرقام مقارنة.

## المرحلة C — تقليل الموارد
- قياس Openbox/LightDM/GTK3/Bevy/NetSurf أولًا ثم استبدال أو إزالة المكونات ذات الأثر الأكبر.
- تفعيل preload بعد موافقة المستخدم ووجود نتائج تثبت أن تدفئة cache تحسّن الفتح دون ضغط الذاكرة.
- إبقاء 3D splash اختياريًا مع fallback ثنائي الأبعاد للرسوم الضعيفة.

## المرحلة D — تأمين سلسلة الإقلاع
- مراجعة مستقلة لـ initramfs guard، موثوقية مفتاح X.509، وسياسة Secure Boot/MOK.
- لتقاوم العبث بملفات initramfs نفسها، يلزم توقيع سلسلة الإقلاع/UKI أو آلية verified boot؛ وحدة خارجية وحدها لا تحقق ذلك.
- وضع وثيقة استرداد واضحة؛ لا يمكن منع مالك الجهاز من التحكم الكامل بالعتاد إذا كان يملك مفاتيح الإقلاع.

## المرحلة E — اكتمال UX
- شاشة greeter آمنة بتكامل رسمي مع LightDM/PAM، لا تخزن ولا تسجل كلمات المرور.
- استخدام نموذج تنين ثلاثي الأبعاد حقيقي وخط عربي مع shaping وextrusion، ثم توثيق فيديو 60 ثانية من إصدار محدد.
- استكمال معاينات الصور والفيديو وPDF وتبويبات الملفات وميزات المحرر LSP حسب أولويات الموارد.
