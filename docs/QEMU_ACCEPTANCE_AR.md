# ISO-X 0.4.0 — مصفوفة قبول QEMU

**قاعدة مهمة:** تشغيل QEMU وحده لا يعني نجاح الاختبار. لا تحول الحالة إلى Pass إلا بعد مشاهدة النتيجة وحفظ سجل/لقطة شاشة مؤرخة تخص نفس SHA-256 من ملف ISO الذي اختُبر.

## تجهيز واختبار

```bash
./tests/qemu-acceptance.sh check ./ISO-X-0.4.0-live-amd64.iso
./tests/qemu-acceptance.sh bios ./ISO-X-0.4.0-live-amd64.iso
./tests/qemu-acceptance.sh uefi ./ISO-X-0.4.0-live-amd64.iso
./tests/qemu-acceptance.sh install ./ISO-X-0.4.0-live-amd64.iso
```

وضع `install` ينشئ قرص QEMU افتراضيًا جديدًا بحجم 24 GiB داخل مجلد الأدلة؛ لا تستخدم قرصًا فعليًا. إذا احتجت إلى تكرار الاختبار، اختر مجلد أدلة جديدًا. لا تشغّل التثبيت على قرص الجهاز الحقيقي.

## قائمة الاختبارات الـ11

| # | الاختبار | الدليل المطلوب | الحالة الحالية |
|---:|---|---|---|
| 1 | تحقق بنية ISO وبصمة SHA-256 وبيانات El Torito | `iso-preflight.txt` وبصمة محفوظة | غير منفذ في هذه البيئة |
| 2 | إقلاع BIOS ثم الوصول إلى سطح المكتب | سجل QEMU ولقطة للسطح بعد الدخول | غير منفذ |
| 3 | إقلاع UEFI ثم الوصول إلى سطح المكتب | سجل QEMU ولقطة للسطح بعد الدخول | غير منفذ |
| 4 | اختبار شاشة الإقلاع والشعار والخلفية وقائمة Start والاختصارات | صور مؤرخة وملاحظات | غير منفذ |
| 5 | تشغيل التطبيقات الأساسية ومركز التطبيقات | لقطات لكل تطبيق وتجربة تثبيت/إزالة | غير منفذ |
| 6 | الصوت ومخرج PipeWire ومؤشر مستوى الصوت | مخرجات `wpctl status`/`pactl info` وتجربة صوت مسموعة؛ محاكاة QEMU وحدها ليست دليل جهاز حقيقي | غير منفذ |
| 7 | الشبكة واختبار التنزيل وزمن الاستجابة | `ip a`, `nmcli`, وسجل `isox-speedtest` | غير منفذ |
| 8 | Bluetooth وواجهة Blueman | `bluetoothctl show`, حالة الخدمة وعتاد/محاكاة مناسبة | غير منفذ؛ يحتاج جهاز/USB Bluetooth مناسبًا |
| 9 | تبديل الطيران عبر `rfkill` واستعادة Wi-Fi | `rfkill list`, حالة NetworkManager قبل/بعد | غير منفذ |
| 10 | التثبيت إلى قرص QEMU ثم الإقلاع من القرص المثبت | قرص qcow2 وسجل أول إقلاع بعد إزالة ISO | غير منفذ |
| 11 | الأداء على نواتين وRAM ‏1024 MiB وسلامة وحدة العلامة/سياسة Secure Boot | `performance.txt`, حالة الوحدة، سجلات/صور Secure Boot واختبار فشل مضبوط | غير منفذ |

## حدود الاختبارات

- QEMU الافتراضي لا يثبت توافق Wi-Fi/Bluetooth والطابعة وكرت الشاشة في الأجهزة الواقعية.
- جهاز QEMU قد لا يوفر بيئة Secure Boot مفعّلة افتراضيًا. يلزم Firmware مناسب وشهادة موثوقة لاختبارها، ولا يكفي تشغيل خيار UEFI فقط.
- لا تختبر فشل وحدة العلامة على جهازك الأساسي؛ اختبر نسخة QEMU قابلة للإتلاف فقط، بعد إنشاء لقطة/نسخة احتياطية.
- نجاح اختبار المصدر لا يثبت نجاح ISO أو installer أو الدخول أو قياسات الأداء.
