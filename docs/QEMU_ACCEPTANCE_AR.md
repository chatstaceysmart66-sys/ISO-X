# ISO-X 0.4.0 — مصفوفة قبول QEMU

**قاعدة مهمة:** تشغيل QEMU وحده لا يعني نجاح الاختبار. لا تحول الحالة إلى Pass إلا بعد مشاهدة النتيجة وحفظ سجل/لقطة شاشة مؤرخة تخص نفس SHA-256 من ملف ISO الذي اختُبر.

## بوابة الرسوميات الآلية

- لا يصدر nonce إلا بعد نشاط `graphical.target` وLightDM وXorg، وجلسة `user` نشطة، وعمل Openbox وتطبيق `/usr/share/iso-x/iso_x_gtk.py`، وظهور نافذة عنوانها ISO-X بحجم لا يقل عن 640×480 عبر X11.
- ينتظر QEMU ثلاث ثوانٍ بعد marker قبل لقطة النهاية. يجب أن تكون P6 PPM سليمة؛ تقبل اللقطات المبكرة 320×200 فأكبر، أما لقطة سطح المكتب النهائية فيلزم أن تكون 640×480 فأكبر وتحتوي ألوان خلفية ISO-X ولوحتها وسماويها ضمن تفاوت الالتقاط المحدد في runner. الأسود و1×1 والناقص/المعطوب أو صورة لا تطابق لوحة التطبيق لا تحقق القبول.
- `PASS_BOOT` يعني إقلاع الضيف واجتياز marker وفحص لقطة سطح المكتب وإنهاء QEMU بطلب مقصود من runner مع مجموعة عمليات نظيفة. رمز خروج 0 وحده، وخروج غير مطلوب، والتصعيد إلى SIGKILL، أو فشل QMP/الصورة لا يحقق النجاح.
- فحوص المصدر الوهمية تختبر هذه الشروط فقط؛ لا تستبدل تشغيل ISO مبنية جديدة على BIOS وUEFI وفحص لقطاتها الفعلية.

## سجل CI السابق

التشغيل `39673715501` على commit `9d33b78965c278a6dbae7f03e1f423e2963a731f` بنى مرشحًا تشخيصيًا واجتاز التحقق البنيوي. BIOS وUEFI سجّلا marker و`qemu_exit_code=0`، لكن كود runner القديم صنفهما `QEMU_INFRASTRUCTURE_FAILURE`، وكانت لقطتا النهاية سوداوين بالكامل. صور BIOS الوسيطة كانت أثناء Plymouth وUEFI الوسيطة عند GRUB؛ لا تثبت أي منهما ظهور سطح المكتب. Persistence عبر reboot لم تُختبر. هذه أدلة تاريخية وليست نتيجة للشيفرة الحالية.

## أحدث دليل آلي

في run [39691070776](https://github.com/chatstaceysmart66-sys/ISO-X/actions/runs/39691070776) على commit `0c2a6ecbdbf87c5a7261b23c7098ab05f389ddb0`، نجح source-check وbuild واجتازت الصورة التحقق البنيوي. أظهرت لقطتا BIOS وUEFI النهائيتان نافذة GTK الفعلية لـISO-X، لكن الوظيفتين فشلتا: رفض runner لقطة BIOS المبكرة 720×400، كما لم يتعرف على ألوان الخلفية الملتقطة في الصورتين. صُحح حد الأبعاد المبكرة وتفاوت الألوان بعد هذا التشغيل؛ يجب انتظار run جديد على commit التصحيح قبل إعلان بوابتي BIOS/UEFI ناجحتين. لم تُشغّل persistence عبر reboot، والصورة تظل مرشح CI تشخيصيًا لا إصدارًا.

في run [39742060324](https://github.com/chatstaceysmart66-sys/ISO-X/actions/runs/39742060324) على commit `778dc13cc634146ec2de7e93118331741cf3dc88`، اجتازت source-check وbuild وBIOS وUEFI، وظهرت واجهة سطح المكتب في النمطين. فشل `promote` فقط عند إعادة كتابة `/isolinux/live.cfg` المستخرج من ISO للقراءة فقط (`PermissionError`). لم يُرفع artifact normal-boot. التغيير الحالي يستخدم استبدالًا ذريًا، ويختبر integration إعادة إنشاء الصورة وملف metadata؛ نتيجة CI بعد هذا التغيير ما زالت مطلوبة.

## اختبار صورة normal-boot بعد التحويل

بعد نجاح بوابتي المرشح التشخيصي، ينشئ `promote` ISO عادية بإزالة nonce من مدخلي BIOS وUEFI، ثم يشغّل قبول QEMU مستقلًا على الناتج المحوّل (`bios-desktop` و`uefi-desktop`). لا يستخدم هذا المسار nonce: يطلب ظهور لوحة ISO-X ونافذتها في لقطة QMP، ثم يحفظ screenshot وJSON لكل firmware. هذا اختبار فعلي للصورة النهائية المحوّلة، ولا يستنتج التكافؤ من إقلاع المرشح التشخيصي.

يظل `release_eligible=false` و`persistence=NOT_RUN` حتى يُختبر حفظ ملف عبر reboot لضيف USB. Artifact normal-boot هو مرشح اختبار فقط، وليس إصدارًا.

## تجهيز واختبار

```bash
./tests/qemu-acceptance.sh check ./ISO-X-0.4.0-live-amd64.iso
./tests/qemu-acceptance.sh bios ./ISO-X-0.4.0-live-amd64.iso
./tests/qemu-acceptance.sh uefi ./ISO-X-0.4.0-live-amd64.iso
./tests/qemu-acceptance.sh install ./ISO-X-0.4.0-live-amd64.iso
```

وضع `install` ينشئ قرص QEMU افتراضيًا جديدًا بحجم 24 GiB داخل مجلد الأدلة؛ لا تستخدم قرصًا فعليًا. إذا احتجت إلى تكرار الاختبار، اختر مجلد أدلة جديدًا. لا تشغّل التثبيت على قرص الجهاز الحقيقي.

## حدود الاختبارات

- QEMU الافتراضي لا يثبت توافق Wi-Fi/Bluetooth والطابعة وكرت الشاشة في الأجهزة الواقعية.
- جهاز QEMU قد لا يوفر بيئة Secure Boot مفعّلة افتراضيًا. يلزم Firmware مناسب وشهادة موثوقة لاختبارها، ولا يكفي تشغيل خيار UEFI فقط.
- لا تختبر فشل وحدة العلامة على جهازك الأساسي؛ اختبر نسخة QEMU قابلة للإتلاف فقط، بعد إنشاء لقطة/نسخة احتياطية.
- نجاح اختبار المصدر لا يثبت نجاح ISO أو installer أو الدخول أو قياسات الأداء.
